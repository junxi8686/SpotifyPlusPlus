# Spotify++

**Анимированные синхронные тексты внутри Spotify — модуль Xposed / LSPosed (форк с упрощённым китайским)**

Заменяет штатный экран текстов Spotify на действительно удобный: параллельный поиск по нескольким источникам, послоговая синхронизация, переводы, романизация, полноэкранный режим, текст на рабочем столе и в Android Auto.

Неофициальный проект, не связан со Spotify или Spicy Lyrics.

## Что это

Модуль текстов, работающий внутри процесса Spotify, **на основе [Spicy EX](https://github.com/amarinne/spicy-ex)** (автор [amarinne](https://github.com/amarinne)), ориентированный в первую очередь на китайскоязычных слушателей.

**Этот репозиторий — изменённый форк, а не исходный проект.** Авторские права на исходный код принадлежат его автору; изменения этого форка распространяются по той же лицензии **AGPL-3.0** — см. [LICENSE](LICENSE) и [NOTICE](NOTICE).

Он делает одно: **следит за тем, чтобы показанный текст был правильным.**

Штатные тексты Spotify берутся только у его поставщика — для китайских песен это часто традиционные иероглифы и построчная синхронизация. А лучшие тексты для китайской песни обычно лежат в QQ Music или NetEase: упрощённые иероглифы, послоговая синхронизация, перевод. Модуль опрашивает несколько источников **одновременно**, ранжирует все кандидаты по **качеству** — сначала точность тайминга, затем полнота, затем надёжность совпадения, а при равенстве предпочитается упрощённый китайский — и выводит победителя на экран текстов Spotify.

## Возможности

### Получение текстов

- **Шесть источников опрашиваются параллельно** — все включённые источники запрашиваются сразу, самый быстрый пригодный ответ показывается первым и заменяется только тем, что ранжировщик оценил **строго** выше
- **Послоговые тексты** (эффект караоке), четыре уровня тайминга: слог, слово, строка, без тайминга
- **Умное сопоставление** — точный Spotify ID, поиск по названию, взаимный поиск упрощённый↔традиционный, псевдонимы и варианты написания
- **Поиск по названию** — если автоматика не справилась, ищите сами, выбирайте из результатов и получайте текст по ID
- **Список источников** — проверка каждого источника отдельно, статус совпадения, уровень тайминга, перевод и возможности, ручное закрепление
- **Локальный кэш** — полученные тексты сохраняются, повторное воспроизведение не требует новых запросов

### Отображение

- **Переводы** и **романизация / чтения**
- **Полноэкранный режим** (перехватывает штатную страницу текстов Spotify)
- **Текст на рабочем столе** и в **картинке в картинке**
- **Текст в Android Auto** — полноэкранный плеер и карточки
- **Публикация в HyperGlow**
- Режим дуэта, пометки бэк-вокала, карточки для публикации

### Качество совпадения

- **Приоритет упрощённого китайского** — при равном ранге выигрывает упрощённый текст
- Проверка здоровья тайминга — отклоняются документы с нарушенным, выходящим за границы или не совпадающим по длине таймингом
- Фильтрация подозрительных ответов

### Прочее

- **Полный интерфейс на упрощённом китайском**, а также English / 日本語 / 한국어 / Русский
- **Резервное копирование** — настройки, ключи, порядок источников, выбор по каждому треку и весь каталог в одном файле

## Источники текстов

| Источник | Примечание | Нужен ключ |
|---|---|---|
| **SpicyLyrics.org** | Сообщество, высокое качество, часто послогово | ✅ клиентский ключ `sl_pk_` |
| **Spotify** | Штатный (обычно построчно; для китайского может быть традиционный) | ❌ |
| **AMLL** | Послоговая библиотека в стиле Apple Music | ❌ |
| **LRCLIB** | Открытая база текстов | ❌ |
| **QQ Music** | Лучшее послоговое покрытие китайских песен, часто с переводом | ❌ |
| **NetEase Cloud Music** | Широкое покрытие китайских песен, часто с переводом | ❌ |

> **Apple Music исключён** из списка источников.

### Приоритет по умолчанию

```
Слог (Syllable)  >  Слово (Word)  >  Строка (Line)  >  Без тайминга (Static)
```

**Уровень тайминга важнее источника** — послоговый текст из QQ Music побеждает построчный из Spotify, даже если Spotify является «штатным» источником. Возможности источника и письменность сравниваются только при равном тайминге.

### Ключ SpicyLyrics.org

Этому источнику нужен ваш собственный клиентский ключ:

1. Запросите на **https://developers.spicylyrics.org/catalog/spicy-ex**
2. Ключ должен начинаться с **`sl_pk_`**
3. Введите в **Настройки → Клиентский ключ SpicyLyrics.org**

Ключ неподходящего формата не сохраняется, о чём выдаётся сообщение. Без ключа источник пропускается, остальные пять работают как обычно.

## Установка

### Требования

- **Root + LSPosed** (рекомендуется), либо
- **Без root + LSPatch** (патч Spotify вы делаете сами)

> Модуль не работает на непатченном Spotify: он полагается на внедрение через Xposed.

### Шаги

1. Скачайте последний APK из [Releases](https://github.com/junxi8686/SpotifyPlusPlus/releases) и установите
2. Откройте **LSPosed** → **Модули** → включите **Spotify++**
3. В **области действия** отметьте `Spotify`
   - также `Android Auto`, если нужен текст там
4. **Остановите Spotify принудительно** (Настройки → Приложения → Spotify → Остановить)
5. Откройте Spotify заново

> ⚠️ **Шаг 4 обязателен.** Установка APK **не** перезапускает процесс Spotify, а LSPosed загружает модули только при запуске процесса. Пропустив шаг, вы тестируете старый код — это самая частая причина путаницы при диагностике.

## Первый запуск

Просто включите трек — текст появится сам.

Для настройки:

- **Список источников** — кнопка источника на экране текстов: состояние совпадения, отдельная перепроверка, ручное закрепление
- **Настройки** — раздел **Spotify++** внутри настроек Spotify

### Настройка под себя

| Что нужно | Как |
|---|---|
| Послоговый текст в приоритете | Включено по умолчанию |
| Определённый источник первым | Настройки → Порядок источников, переместить вверх |
| Упрощённый китайский | Включено по умолчанию (при равном ранге) |
| Отключить автопрокрутку | Выключить «Следовать за воспроизведением» |
| Текст рассинхронизирован | Настройки → Сбросить синхронизацию |

## Резервное копирование

**Настройки → Экспорт резервной копии** записывает JSON в `Downloads/Spicy EX/SpicyEX-backup.json`.

Содержит:

| Содержимое | Примечание |
|---|---|
| Все настройки | Интерфейс, отрисовка, поведение |
| **Ключи AI API** | Хранятся зашифрованными |
| **Клиентский ключ SpicyLyrics.org** | Хранится зашифрованным |
| **Порядок источников и выбор по трекам** | Ваши настройки приоритета |
| **Весь каталог** | Какие источники есть у каждого трека, как совпало, что проверено |
| Ревизия ключа и состояние доступа SpicyLyrics.org | Чтобы старые результаты не смешались после восстановления |

Восстановление: **Настройки → Импорт резервной копии**, выберите этот JSON.

> **Импорт перезаписывает.** Сначала сделайте экспорт для подстраховки.
> Черновики диагностики и буферы захвата **не входят** — это временное состояние отчёта.
> **Формат обратно совместим**: старые копии импортируются, отсутствующие в файле разделы не трогаются и не очищаются.

## Решение проблем

<details>
<summary><b>Установлено, но ничего не происходит</b></summary>

1. Убедитесь, что модуль включён в LSPosed и **Spotify отмечен в области действия**
2. **Остановите Spotify принудительно и откройте заново** — обязательно
3. Проверьте, что версия Spotify поддерживается (сборка рассчитана на 9.1.88)

</details>

<details>
<summary><b>Текст традиционный, нужен упрощённый</b></summary>

При равном ранге упрощённый выбирается автоматически. Если всё равно традиционный:

1. Откройте **список источников** и посмотрите, есть ли источник с упрощённым послоговым текстом
2. Если есть — закрепите его вручную
3. Если нет — упрощённого текста для этого трека пока не существует

</details>

<details>
<summary><b>Источник ничего не находит</b></summary>

Нажмите на эту строку в **списке источников**, чтобы проверить отдельно:

- **Галочка** → текст для трека есть
- **Крестик** → действительно нет либо сбой сети

Наличие в каталогах **меняется со временем** — отсутствие сегодня не означает отсутствие завтра.

</details>

<details>
<summary><b>SpicyLyrics.org ничего не возвращает</b></summary>

1. Убедитесь, что ключ начинается с `sl_pk_` и сохранился (сообщение выдаётся в любом случае)
2. **Нажмите на него вручную** в списке источников — ручная проверка идёт по пути «явного восстановления» и снимает прежнюю блокировку доступа
3. Ключ, отклонённый сервером, приостанавливает этот источник

</details>

<details>
<summary><b>Восстановление на новом устройстве</b></summary>

Используйте **экспорт/импорт**. Учтите:

- Ключи в файле **зашифрованы**, но ключ шифрования привязан к устройству — после смены устройства **введите ключи заново**
- Остальное (настройки, порядок источников, каталог) восстанавливается нормально

</details>

<details>
<summary><b>Текст рассинхронизирован</b></summary>

Настройки → **Сбросить синхронизацию текстов**. Смещение очищается, модуль заново привязывается к часам воспроизведения.

</details>

## Известные проблемы

- Некоторые треки медленно сопоставляются на редких источниках (задержка сети, не модуль)
- Текст в Android Auto мало проверен на разных головных устройствах
- У единичных треков длина текста не совпадает с записью (проверка превышения отсекает большинство)

Сообщайте о проблемах в [Issues](https://github.com/junxi8686/SpotifyPlusPlus/issues), приложив:

- версию Spotify
- версию модуля
- шаги воспроизведения
- скриншоты

## Что изменено в этом форке

Репозиторий объединяет [Spicy EX](https://github.com/amarinne/spicy-ex) **v2.0.0** с **v1.1** этого проекта со следующими изменениями:

### Упрощённый китайский

- Добавлен `values-zh-rCN`, покрывающий все строковые ресурсы
- Исправлены строки, на которые Java ссылалась, но которых не было в ресурсах, из-за чего китайский интерфейс откатывался к английскому
- Локализованы динамические тексты: строка авторства текста, сообщения об ошибках
- Исправлены устройства, где список языков показывал только текущий язык и не давал вернуться

### Сопоставление текстов

- **Ранжирование по качеству** — в v2.0.0 upstream перешёл на «сначала источник» (выбрать основной источник и сравнивать тайминг только внутри него), из-за чего лучший запасной источник никогда не мог заменить основной. Возвращено к «тайминг > полнота > надёжность совпадения > поставщик» с приоритетом упрощённого
- **Параллельный запрос к нескольким источникам** — upstream опрашивал источники по очереди, и ожидание равнялось их сумме; теперь они опрашиваются сразу, первым показывается пригодный ответ, замена только при **строго** лучшей оценке
- **Поиск по названию** — при неудаче автоматики ищите и выбирайте сами
- Взаимный поиск упрощённый↔традиционный и варианты псевдонимов
- **Список источников проверяет каждый трек один раз** и больше не сообщает о каждом успехе

### Прочее

- **Apple Music исключён**
- **Резервное копирование расширено с 2 хранилищ до 6** — upstream копировал только настройки и ключи, поэтому после восстановления каталог был пуст, а источники не выбраны
- Исправлены три ссылки GitHub, указывавшие на адреса без имени репозитория
- Удалён пункт «Сообщить о проблеме» (черновики уходили в трекер upstream, а не в этот форк)
- Адаптировано получение трека для Spotify 9.1.88 (подход upstream бросает `NoSuchMethodException`, из-за чего автоматический поиск полностью отключается)

Подробнее: [MODIFICATIONS.md](MODIFICATIONS.md) и [FEATURES_USER.md](FEATURES_USER.md).
