# 修改说明

本仓库是基于 Spicy EX 项目（AGPL-3.0）的修改版。

依据 AGPL-3.0 §5(a)（修改版本必须显著声明修改与日期），列出改动如下。

- 修改者：The Spotify++ project
- 起始时间：2026-10
- 上游基线：Spicy EX v2.1.4（已含 v2.1.0；本版在其基础上继续修改）

## 改动清单

### 界面与本地化
- 新增 `values-zh-rCN`，覆盖 751 条字符串
- 补齐 9 条「Java 引用但资源未声明」的字符串，修复中文界面回退英文
- 应用名改为 `Spotify++`，包名改为 `com.spotifyplusplus`，版本号改为 `1.0`
- 重绘应用图标（自适应矢量图标）
- 修复语言列表只显示当前语言、导致切不回中文的问题

### 新增功能
- **按名称搜索歌词**：选来源 → 输入 → 结果列表 → 手动点选，按 ID 直接取词
- **导出 / 导入设置与数据**：使用 SAF 原生文件选择器
- **清除本模块的所有内容**（1.6.1 起）：设置 → 关于与诊断，一次性清除本模块写入的数据库、缓存、设置、加密密钥、字体/语言包、诊断草稿与 agent 通道；不动 Spotify 自身数据与已导出的备份，清完需重启 Spotify
- **翻译后端可选**：新增一个自带账号的翻译接口（官方 API，需自备 AppID 与密钥，供默认的在线翻译不可达的网络使用），默认仍是不需要账号的在线翻译，另可只显示歌词来源自带的翻译
- **背景模糊强度可调**（1.6.1 起，相对上游新增）：布局编辑器 → 背景分组 →「背景模糊」，50–200%，同时缩放模糊带高度与半径；1.6.2 起默认 100%，即上游带宽与半径逐字节一致，控制保留供调高（`Settings.LYRICS_BACKDROP_BLUR`）。同分组的「背景变暗」保持上游线性曲线（0→1.0、默认 35→0.65、100→黑）：1.6.2 撤销了 1.6.1 的二次曲线，因为用户核对后指出浅端必须保持上游亮度

### 匹配与搜索
- 简繁折叠（`ChineseScriptVariants`）与标题分隔符归一化
- 首次搜索简体写法优先
- 来源排序：自带翻译/转写优先于源顺序
- 部分来源空结果退避重试
- AI 候选裁决（本地判据全拒时才调用）

### 修复
- 来源面板「检查中」看门狗不解锁行（`disarmed()` → `finished()`）
- SAF 请求码超过 16 位导致 androidx 宿主拒绝
- 备份导入版本校验逃逸 try 导致界面无反馈
- 移除可能使 Spotify 崩溃的模型写入（默认关闭的强力清除除外）

### 相对上游的取舍（1.6）
- **导出 / 导入设置与数据**：保留本仓的备份恢复入口（上游没有）。合并时该入口一度丢失（面板换成上游注册表驱动，动作行未重新登记），1.6.0 已恢复为面板的独立「备份」分组，1.6.1 补上图标
- **自定义字体路径编辑**：保留（上游没有），入口在布局编辑器的字体分组里
- **SpicyLyrics.org 客户端密钥的「显示」**：保留（上游没有）
- **「Spicy 手动令牌」**：1.6.1 已删除。它是死开关（读取分支被恒定 `false` 挡死），且服务的旧传输通道已废弃；相关设置项、面板行、对话框、存储类与字符串一并移除。同属"实验性旧实现"清理，不涉及上游
- **「忽略 Spotify 自带歌词」开关**：早期版本已移除，不是本仓现有功能。当时的实现在清空 Spotify 歌词字段时破坏了歌词捕获，并把空串写进 Spotify 自己的歌词表；隐藏原生卡片的尝试也因 Compose 语义树在应用内不可读而主动停用。两条孤儿字符串与 `SpotifyLyricsCardHider` 死代码仍在，若要做等价能力，现在的做法是在来源列表里关掉 Spotify
- **配套应用推送**：保留本仓自己的「未安装配套应用就不推送歌词」修复；上游没有 `SpicyBridgeBackoff` 这条逐级退避的阶梯
- **来源排序与评分**：保留本仓的歌词来源排序与评分表，不改为上游的替代规则；2026-10-29 起该表恢复上游 v2.1.4 的七项来源顺序（Apple Music 第二位），评分规则本身仍是本仓的
- **面板与本地化**：保留本仓的面板与设置项结构，以及全量中文本地化（809 个键）
- **翻译行排版**：上游把译文画成**斜体 + 次要字号**（`LyricsRowViewFactory`）；本仓按用户对照要求改为**正体、常规字重、默认主行 62%** 并新增「翻译字号」设置（40–100%，`Settings.TRANSLATION_TEXT_SIZE`）；当前句译文随主行同步提亮（`LyricsLineViewState.applyLineLevelGradient` 现同时作用于 `translationView`）。仅影响全屏歌词的动态译文行；静态投影面（车机）仍用原有静态次要文本
- **桥接机制**：上游的桥接实现已并入本仓（按方法合并 provider、drain/clear 顺序、字符形式投影），在上述保留项之下工作
- **Apple Music**：**2026-10-29 起恢复为正常歌词来源**（用户明确要求，代码与上游 v2.1.4 一致，并加入来源竞选与评分）：默认开启、默认顺序第二位、自动竞选第一轮即询问、`check apple` 可用；同名动效风格一直保留。`Spicy` 旧桌面令牌别名仍在退役集合，不随之恢复
