# Spotify++ 1.6.2

本版在 1.6.1 的基础上继续打磨歌词界面的观感，并修掉两处「设置改了没反应」的问题。

## 变更

- **翻译行字号变小并开放调节**：默认从主行的 70% 降到 **62%**；新增「翻译字号」设置（40%–100%），位置在 **设置 → 翻译**，紧跟「翻译亮度」。
- **翻译字重与主歌词联动**：主歌词用粗体，翻译也跟着粗；主歌词是常规，翻译也常规。不再由翻译自己单独定一套。
- **当前句的翻译保持灰色**：主歌词高亮时，翻译**不**跟着变亮，和 Apple Music 一致。
- **「背景变暗」最浅档真正变亮**：除了把亮度曲线改回上游的线性算法，还加了一道门限——「背景变暗」低于 15 时不再套用那层固定的 0.38 强暗化。此前只要不是 0 就会整块压暗，所以最浅一档也偏黑；现在 0 和 5 都是亮的，深暗只在你明显要暗的时候出现。
- **顶部模糊的参数回到原版**：上一版新增的「背景模糊」默认值从 150% 改成 **100%**，此数值下模糊带高度、半径、渐隐全部与上游一致（等于没改动）。想要更重可以自己拉到 200%。
- **Apple 动效补了两处帧驱动**：确认「载入升起 / Apple 式滑动 / Apple 上浮 / 淡出已唱过的行」四个开关加两个滑杆的渲染链与上游一致后，补上了「动画开始时请求帧」的两处缺口（歌曲切换入场动画、载入入场动画），让不依赖滚动触发的上浮也能拿到帧。
  - 同时加了一行诊断日志（标签 `appleMotion`，仅在开启调试日志时输出），用来判断"没有帧"还是"位移算出来是 0"。

## 已知未解决

- **仿 Apple Music 的上浮效果**：代码路径与上游一致，但仍需真机日志确认到底是帧没驱动起来，还是这次上浮的位移被判定为 0。本版带诊断日志，抓到一次日志即可定位。
- 上浮效果本身需要把「动画样式」选成 **Apple Music**（或把「行内动效」选成 Apple lift）才会出现，默认组合下本来就不触发。
- 桥接的存在性探测中「未安装」分支只有单元测试覆盖；真机需要安装 HyperGlow 配套应用才能验证。
- 日语、韩语、俄语 README 的本地化仍有历史缺口，非本次引入。
