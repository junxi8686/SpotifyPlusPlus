# Spotify++ 1.6.1

本版在 1.6.0（已合并上游 v2.1.0 + v2.1.4）的基础上继续修，功能集有增有减。

## 变更

- **删除「Spicy 手动令牌」**：它是个死开关——能填、能存、能备份、能显示，但读它的两条分支被恒定的 `false` 挡死，而它服务的旧传输通道也已废弃（SpicyLyrics.org 现在只认 `sl_pk_` 客户端密钥）。填了不会生效，留着只会误导，故移除。**「SpicyLyrics.org 客户端密钥」不受影响**，那一个才是真正在用的。
- **导出 / 导入补上图标**：这两行之前是纯文字，现在跟面板其它行一致（导出用保存图标，导入用还原图标）。
- **新增「清除本模块的所有内容」**（设置 → 关于与诊断）：一次性清掉本模块自己写的所有数据——歌词目录数据库、响应缓存、AI 付费账本、设置、加密保存的各类密钥、字体与语言包、诊断草稿与截图、agent 通道等。
  - 只清本模块的，**不动 Spotify 自己的数据库、已下载的歌和账号数据**
  - 已导出到下载目录的备份文件**不会被删**（那是恢复用的路径）
  - 会二次确认，并明确告知「设置和已保存的密钥也会丢失」
  - 清完需要重启 Spotify 才完全生效
  - 用途：导入旧备份后出现异常、或者想把模块恢复成全新状态时，用它比逐个清缓存干净
- **恢复 Apple Music 作为歌词来源**：它会出现在来源面板（第二位，紧跟 SpicyLyrics.org 之后），默认启用，参与自动竞选与评分，也可以单独点它检查。代码按上游 v2.1.4 原样恢复。
  - ⚠️ 注意：当初移除它的理由是"Apple 的公开接口不再返回可用歌词"。现在接口路径已经通、模块会正常去请求，但如果对方接口确实取不到，这一行会显示失败——那是上游自身状态，不是本模块的问题。
- **修好顶部模糊**：以前把「歌曲信息背景」设成模糊时，遮罩被藏起来、模糊却没启动，导致歌词清晰地压在专辑封面和歌名上面。现在按上游补上了那一处漏掉的调用，歌词经过头部时会在模糊带里虚化。
- **新增「背景模糊」设置**（布局编辑器 → 背景）：50%–200%，默认 150%。往高调可以加强模糊带的深度与强度，调到 100% 即与上游原版一致。
- **「背景变暗」曲线重做**：原来是一根直线，调到中间几乎没变化、调到头直接全黑。现在改成缓和的曲线，中间档位真正可用，100 也不再是纯黑。
- **翻译行排版**：翻译文字从**斜体 + 偏小**改为**正体 + 约主行 0.7 倍**，与 Apple Music 的观感一致。

## 关于「仿 Apple Music 上浮」

它不是缺失，默认组合下不触发。想看到有两种方式，任选其一：

- 把「动效风格」选成 **Apple Music**（Apple 上浮开关默认就是开的），或
- 在任意动效风格下，把「行内动效」选成 **Apple lift**

顶部渐隐本身与上游逐行一致，不是丢失项。

- 签名与 1.5 / 1.6.0 相同，不需要卸载
- 版本号 1.6.1 / versionCode 13

## 如果升级后出现异常，先清一次本地存储

从旧版升上来后，如果遇到来源面板显示不对、某首歌一直"检查中"、明明有歌词却显示找不到这类现象，通常是旧版留下的本地状态和新版本对不上。按影响从小到大：

1. 设置 → 歌词来源 → 「清除已保存的歌词」（只清本模块的候选与状态）
2. 系统设置 → 应用 → Spotify → 存储 → 清除缓存（不退出登录、不删下载）
3. 系统设置 → 应用 → Spotify → 存储 → 清除存储（会退出登录、删下载，最后手段）
4. 或者直接用新加的「清除本模块的所有内容」
