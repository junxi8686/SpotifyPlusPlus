# Spotify++

**Spotify 안의 애니메이션 동기화 가사 — Xposed / LSPosed 모듈 (중국어 간체 포크)**

Spotify 기본 가사 화면을 제대로 쓸 수 있는 것으로 바꿉니다: 여러 소스 동시 검색, 글자 단위 가사, 번역, 로마자 표기, 전체 화면 렌더링, 데스크톱 가사, Android Auto 가사.

비공식 프로젝트이며 Spotify, Spicy Lyrics와 무관합니다.

## 무엇인가

Spotify 프로세스 안에서 동작하는 가사 모듈로, **[Spicy EX](https://github.com/amarinne/spicy-ex)**(제작 [amarinne](https://github.com/amarinne))를 기반으로 주로 중국어권 사용자를 위해 수정한 것입니다.

**이 저장소는 수정된 포크이며 원본 프로젝트가 아닙니다.** 상류의 저작권은 원저자에게 있고, 이 포크의 변경분도 동일하게 **AGPL-3.0**으로 배포됩니다 — [LICENSE](LICENSE)와 [NOTICE](NOTICE)를 참고하세요.

하는 일은 하나입니다: **보이는 가사가 올바른 것이 되게 만듭니다.**

Spotify 기본 가사는 자체 공급자 것만 쓰기 때문에 중국어 곡에서는 번체·줄 단위인 경우가 많습니다. 반면 중국어 곡의 가장 좋은 가사는 QQ Music이나 NetEase에 있습니다 — 간체, 글자 단위, 번역 포함. 이 모듈은 여러 가사 소스에 **동시에** 질의하고, 받은 후보를 **품질**로 순위를 매깁니다 — 시간축 정밀도 우선, 다음 완전성, 다음 일치 확실성, 동순위에서는 간체 우선 — 그리고 가장 좋은 것을 Spotify 가사 화면에 렌더링합니다.

## 기능

### 가사 가져오기

- **6개 소스 동시 검색** — 활성화된 모든 소스에 동시에 질의하고, 가장 빨리 쓸 수 있는 답이 먼저 표시되며, 순위기가 **엄격히** 더 높게 평가할 때만 교체됩니다
- **글자 단위 가사**(노래방 효과), 음절·단어·줄·시간축 없음의 4단계
- **스마트 매칭** — Spotify ID 정확 일치, 제목 검색, 간체↔번체 상호 검색, 별칭과 표기 변형
- **이름으로 검색** — 자동 매칭이 실패하면 직접 제목을 검색해 결과에서 고르고 ID로 가져옵니다
- **가사 소스 목록** — 소스별 개별 확인, 일치 상태·시간축 수준·번역·기능 표시, 수동 우선 지정
- **로컬 캐시** — 가져온 가사는 저장되어 같은 곡을 다시 재생할 때 재요청이 필요 없습니다

### 가사 표시

- **번역**과 **로마자 / 독음**
- **전체 화면 가사**(Spotify 기본 가사 페이지 대체)
- **데스크톱 가사**와 **PiP(화면 속 화면)** 가사
- **Android Auto 가사** — 전체 화면 플레이어와 카드
- **HyperGlow** 가사 전송
- 듀엣 보기, 배경 보컬 표시, 공유 카드

### 매칭 품질

- **간체 우선** — 동순위면 간체가 이기므로 "간체가 있는데 번체가 나오는" 일이 없습니다
- 시간축 건강 검사 — 깨졌거나 범위를 벗어나거나 곡 길이와 맞지 않는 문서를 거부
- 오염 문서 필터 — 의심스러운 응답을 거부

### 기타

- **완전한 중국어 간체 UI**, 그 외 English / 日本語 / 한국어 / Русский
- **백업과 복원** — 설정, 키, 소스 순서, 곡별 선택, 전체 카탈로그를 한 파일로

## 가사 소스

| 소스 | 설명 | 키 필요 |
|---|---|---|
| **SpicyLyrics.org** | 커뮤니티 가사 라이브러리, 품질 높고 글자 단위가 많음 | ✅ `sl_pk_` 클라이언트 키 |
| **Spotify** | Spotify 기본(대개 줄 단위, 중국어는 번체일 수 있음) | ❌ |
| **AMLL** | Apple Music 계열 글자 단위 라이브러리 | ❌ |
| **LRCLIB** | 개방형 가사 데이터베이스 | ❌ |
| **QQ Music** | 중국어 곡 글자 단위 범위가 가장 넓고 번역이 많음 | ❌ |
| **NetEase Cloud Music** | 중국어 곡 범위가 넓고 번역이 많음 | ❌ |

> **Apple Music은 제거되었습니다.** 더 이상 가사 소스로 쓰지 않습니다.

### 기본 우선순위

```
음절 (Syllable)  >  단어 (Word)  >  줄 (Line)  >  시간축 없음 (Static)
```

**시간축 수준이 소스 정체성보다 우선합니다** — Spotify가 "기본" 소스여도 QQ Music의 글자 단위 가사가 Spotify의 줄 단위 가사를 이깁니다. 동일 수준일 때만 소스 능력과 간체/번체를 비교합니다.

### SpicyLyrics.org 키

이 소스는 본인의 클라이언트 키가 필요합니다:

1. **https://developers.spicylyrics.org/catalog/spicy-ex** 에서 신청
2. 키는 **`sl_pk_`** 로 시작해야 합니다
3. **설정 → SpicyLyrics.org 클라이언트 키**에 입력

형식이 맞지 않으면 저장이 거부되고 안내가 표시됩니다. 키가 없으면 이 소스는 자동으로 건너뛰고 나머지 5개는 정상 동작합니다.

## 설치

### 요구 사항

- **루트 + LSPosed**(권장), 또는
- **루트 없음 + LSPatch**(Spotify 패치는 직접)

> 패치되지 않은 Spotify에서는 동작하지 않습니다. Xposed 프레임워크 주입에 의존합니다.

### 단계

1. [Releases](https://github.com/junxi8686/SpotifyPlusPlus/releases)에서 최신 APK를 받아 설치
2. **LSPosed** → **모듈** → **Spotify++** 활성화
3. **범위**에서 `Spotify` 체크
   - Android Auto 가사도 원하면 `Android Auto` 추가
4. **Spotify 강제 종료**(설정 → 앱 → Spotify → 강제 종료)
5. Spotify 다시 열기

> ⚠️ **4단계는 생략할 수 없습니다.** APK 설치는 Spotify 프로세스를 **재시작하지 않으며**, LSPosed는 프로세스 시작 시에만 모듈을 로드합니다. 생략하면 옛 코드를 테스트하게 됩니다 — 문제 해결에서 가장 흔한 혼란의 원인입니다.

## 첫 실행

설치 후 곡을 재생하면 가사가 자동으로 나타납니다.

조정이 필요하면:

- **가사 소스 목록** — 가사 화면의 소스 버튼으로 각 소스의 일치 상황 확인, 개별 재확인, 수동 지정
- **설정** — Spotify 설정 안의 **Spotify++** 섹션

### 조정 예

| 원하는 것 | 방법 |
|---|---|
| 글자 단위 가사 우선 | 기본 활성화, 설정 불필요 |
| 특정 소스 우선 | 설정 → 소스 순서에서 맨 앞으로 이동 |
| 중국어 곡을 간체로 | 기본 활성화(동순위에서 간체 우선) |
| 자동 따라가기 끄고 수동 스크롤 | "재생 따라가기" 끄기 |
| 가사가 어긋남 | 설정 → 가사 동기화 재설정 |

## 백업과 이전

**설정 → 백업 내보내기**는 `Downloads/Spicy EX/SpicyEX-backup.json`에 JSON을 씁니다.

포함 내용:

| 내용 | 비고 |
|---|---|
| 모든 설정 | 화면·렌더링·동작 옵션 |
| **AI API 키** | 암호화 저장 |
| **SpicyLyrics.org 클라이언트 키** | 암호화 저장 |
| **소스 순서와 곡별 선택** | 조정한 우선순위 |
| **전체 카탈로그** | 각 곡이 어떤 소스 후보를 갖는지, 일치 방식, 확인 여부 |
| SpicyLyrics.org 키 개정과 접근 상태 | 복원 후 옛 결과가 섞이지 않도록 |

복원은 **설정 → 백업 가져오기**에서 그 JSON을 선택합니다.

> **가져오기는 덮어쓰기입니다.** 먼저 한 번 내보내 두는 것이 안전합니다.
> 진단 초안과 캡처 버퍼는 **포함되지 않습니다** — 진행 중인 보고서의 임시 상태이기 때문입니다.
> **형식은 하위 호환**입니다: 옛 백업도 가져올 수 있고, 파일에 없는 항목은 그대로 두며 지우지 않습니다.

## 소스에서 빌드

### 툴체인

| 항목 | 버전 |
|---|---|
| JDK | 17 |
| Android SDK | Platform 35 (compileSdk 35 / minSdk 27) |
| Gradle | 8.14.2 (wrapper 포함) |
| Android Gradle Plugin | 8.8.2 |

### 명령

```bash
git clone https://github.com/junxi8686/SpotifyPlusPlus.git
cd SpotifyPlusPlus
./gradlew :app:assembleDebug          # 결과: app/build/outputs/apk/debug/
./gradlew :app:testDebugUnitTest      # 단위 테스트
```

Windows에서는 `gradlew.bat`을 사용하세요.

## 문제 해결

<details>
<summary><b>설치했는데 아무 반응이 없음</b></summary>

1. LSPosed에서 모듈이 활성화되고 **범위에 Spotify가 체크**되었는지 확인
2. **Spotify 강제 종료 후 다시 열기** — 필수
3. Spotify 버전이 지원 범위인지 확인(이 빌드는 9.1.88 대응)

</details>

<details>
<summary><b>번체로 나오는데 간체를 원함</b></summary>

동순위면 간체가 자동 우선됩니다. 그래도 번체라면:

1. **가사 소스 목록**에서 간체 글자 단위를 제공하는 소스가 있는지 확인
2. 있으면 수동으로 맨 앞에 고정
3. 없으면 그 곡에 아직 간체 가사가 없는 것입니다

</details>

<details>
<summary><b>특정 소스가 계속 못 찾음</b></summary>

**가사 소스 목록**에서 그 줄을 눌러 개별 확인하세요:

- **체크** → 그 소스에 이 곡의 가사가 있음
- **엑스** → 정말 없거나 네트워크 실패

카탈로그 수록 여부는 **변동됩니다** — 오늘 없다고 내일도 없다는 뜻은 아닙니다.

</details>

<details>
<summary><b>SpicyLyrics.org가 아무것도 반환하지 않음</b></summary>

1. 키가 `sl_pk_`로 시작하고 저장에 성공했는지 확인(결과는 반드시 표시됩니다)
2. 소스 목록에서 **한 번 수동으로 탭** — 수동 확인은 "명시적 복구" 경로를 타서 이전 접근 차단을 해제합니다
3. 서버가 거부한 키는 해당 소스를 일시 중지시킵니다

</details>

<details>
<summary><b>기기 변경 후 복원</b></summary>

**백업 내보내기/가져오기**를 사용하세요. 주의:

- 키는 파일 안에서 **암호화**되지만 암호화 키는 기기에 묶여 있습니다 — 기기를 바꾸면 **키를 다시 입력**해야 합니다
- 그 외(설정, 소스 순서, 카탈로그)는 정상 복원됩니다

</details>

<details>
<summary><b>가사가 어긋남</b></summary>

설정 → **가사 동기화 재설정**. 저장된 오프셋을 지우고 재생 시계에 다시 고정합니다.

</details>

## 알려진 문제

- 일부 곡은 마이너 소스에서 일치가 느립니다(네트워크 요인이며 모듈 문제가 아닙니다)
- Android Auto 가사는 차량 헤드유닛에서 충분히 검증되지 않았습니다
- 극소수 곡에서 가사 길이가 곡과 맞지 않습니다(길이 초과 검사로 대부분 걸러집니다)

문제는 [Issues](https://github.com/junxi8686/SpotifyPlusPlus/issues)에 다음을 포함해 알려주세요:

- Spotify 버전
- 모듈 버전
- 재현 단계
- 관련 스크린샷

## 이 포크의 변경 사항

이 저장소는 [Spicy EX](https://github.com/amarinne/spicy-ex) **v2.0.0**을 이 프로젝트의 **v1.1**에 병합하고 다음을 조정했습니다:

### 중국어 간체

- `values-zh-rCN` 추가, 모든 문자열 리소스 포함
- 상류에서 "Java는 참조하지만 리소스에 없는" 문자열 때문에 중국어 UI가 영어로 되돌아가던 문제 수정
- 가사 크레딧, 오류 메시지 등 동적 문구 현지화
- 일부 기기에서 언어 목록이 현재 언어만 보이고 되돌아오지 못하던 문제 수정

### 가사 매칭

- **품질 우선 순위** — 상류 v2.0.0은 "소스 우선"(주 소스를 정하고 그 안에서만 시간축 비교)으로 바꿔 더 나은 대체 소스가 주 소스를 대체할 수 없게 했습니다. 이 포크는 "시간축 > 완전성 > 일치 확실성 > 제공자"로 되돌리고 간체 우선을 유지합니다
- **여러 소스 동시 요청** — 상류는 하나씩 순차 요청이라 대기가 모든 소스의 합이었습니다. 이제 동시에 요청하고 가장 먼저 쓸 수 있는 것을 표시하며 **엄격히** 더 높을 때만 교체합니다
- **이름으로 검색** — 자동 매칭 실패 시 직접 검색해 선택
- 간체↔번체 상호 검색과 별칭 변형("한 글자 차이를 다른 곡으로 취급"하던 문제 수정)
- **소스 목록은 곡당 한 번만 확인**하고, 성공할 때마다 알리지 않습니다

### 기타

- **Apple Music 소스 제거**
- **백업을 2개 저장소에서 6개로 확장** — 상류는 설정과 키만 백업해서 복원하면 카탈로그가 비고 소스가 선택되지 않았습니다
- 저장소 이름이 없는 잘못된 GitHub 링크 3곳 수정
- 설정의 "문제 보고" 제거(초안이 상류 트래커로 가서 이 포크에는 오지 않습니다)
- Spotify 9.1.88 곡 조회 대응(상류 방식은 `NoSuchMethodException`을 던져 자동 검색이 완전히 멈춥니다)

자세한 내용은 [MODIFICATIONS.md](MODIFICATIONS.md)와 [FEATURES_USER.md](FEATURES_USER.md)를 참고하세요.
