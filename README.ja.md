# Spotify++

**Spotify の中にアニメーション同期歌詞を —— Xposed / LSPosed モジュール（簡体字中国語版フォーク）**

Spotify 標準の歌詞画面を、実用的なものに置き換えます：複数ソースの同時検索、逐字（カラオケ）歌詞、翻訳、ルビ／ローマ字、全画面表示、デスクトップ歌詞、Android Auto 歌詞。

非公式プロジェクトです。Spotify および Spicy Lyrics とは無関係です。

## これは何か

Spotify のプロセス内で動作する歌詞モジュールです。**[Spicy EX](https://github.com/amarinne/spicy-ex)**（作者 [amarinne](https://github.com/amarinne)）をベースに、主に中国語圏の利用者向けに改変したものです。

**このリポジトリは改変版であり、本家プロジェクトではありません。** 上流の著作権は原作者に帰属し、このフォークの変更部分も同じ **AGPL-3.0** で公開されています —— [LICENSE](LICENSE) と [NOTICE](NOTICE) を参照してください。

やることはひとつ：**表示される歌詞が正しいものになるようにする**。

Spotify 標準の歌詞は自社プロバイダのものだけで、中国語曲では繁体字・行単位のことがよくあります。一方、中国語曲の最良の歌詞は QQ Music や NetEase にあり、簡体字・逐字・翻訳付きであることが多いのです。本モジュールは複数の歌詞ソースへ**同時に**問い合わせ、取得した候補を**品質**で順位付けします —— 時間軸の精度を最優先、次に完全性、次に一致の確実さ、同順位では簡体字を優先 —— そして最良のものを Spotify の歌詞画面に描画します。

## 機能

### 歌詞の取得

- **6 つのソースを同時検索** —— 有効なソースすべてに同時に問い合わせ、最も速く使えるものが先に表示され、ランカーが厳密に高く評価した場合のみ置き換わります
- **逐字歌詞**（カラオケ表示）、時間軸は音節・単語・行・時間軸なしの 4 段階
- **スマートマッチング** —— Spotify ID 完全一致、曲名検索、簡体字↔繁体字の相互検索、別名・表記ゆれ（例：`反乌托邦 - 拼接版` と `拼接乌托邦`）
- **曲名で検索** —— 自動一致に失敗したら自分で曲名を検索し、結果から選んで ID で取得
- **歌詞ソース一覧** —— ソースごとに個別チェック、一致状況・時間軸レベル・翻訳・機能を表示、手動で優先指定も可能
- **ローカルキャッシュ** —— 取得済みの歌詞は保存され、同じ曲の再生で再取得は不要

### 歌詞の表示

- **翻訳**と**ルビ／ローマ字**
- **全画面歌詞**（Spotify 標準の歌詞ページを置き換え）
- **デスクトップ歌詞**と**ピクチャインピクチャ**歌詞
- **Android Auto 歌詞** —— 全画面プレイヤーとカード
- **HyperGlow** への歌詞配信
- デュエット表示、バックコーラス印、共有カード

### マッチ品質

- **簡体字優先** —— 同順位なら簡体字が勝つため、「簡体字があるのに繁体字が出る」ことがなくなります
- 時間軸の健全性検査 —— 破損・範囲外・楽曲長と不一致な時間軸を拒否
- 汚染文書のフィルタ —— 疑わしいレスポンスを拒否

### その他

- **簡体字中国語の完全な UI**、ほかに English / 日本語 / 한국어 / Русский
- **バックアップと復元** —— 設定・キー・ソース順序・曲ごとの選択・カタログ全体を 1 ファイルに

## 歌詞ソース

| ソース | 説明 | キー |
|---|---|---|
| **SpicyLyrics.org** | コミュニティ歌詞ライブラリ。高品質で逐字も多い | ✅ `sl_pk_` クライアントキーが必要 |
| **Spotify** | Spotify 標準（多くは行単位、中国語は繁体字のことも） | ❌ |
| **AMLL** | Apple Music 系の逐字歌詞ライブラリ | ❌ |
| **LRCLIB** | オープンな歌詞データベース | ❌ |
| **QQ Music** | 中国語曲の逐字カバレッジが最も広く、翻訳も多い | ❌ |
| **NetEase Cloud Music** | 中国語曲のカバレッジが広く、翻訳も多い | ❌ |

> **Apple Music は削除されました。** 歌詞ソースとして使用しません。

### 既定の優先順位

```
逐字 (Syllable)  >  逐語 (Word)  >  行 (Line)  >  時間軸なし (Static)
```

**時間軸のレベルはソースの素性より優先されます** —— Spotify が「標準」ソースであっても、QQ Music の逐字歌詞は Spotify の行単位歌詞に勝ちます。同レベルのときだけソース能力と簡体／繁体を比較します。

### SpicyLyrics.org のキー

このソースにはご自身のクライアントキーが必要です：

1. **https://developers.spicylyrics.org/catalog/spicy-ex** で申請
2. キーは **`sl_pk_`** で始まる必要があります
3. **設定 → SpicyLyrics.org クライアントキー** に入力

形式が合わないキーは拒否され、その旨が表示されます。キーがない場合、このソースは自動的にスキップされ、残り 5 つは通常どおり動作します。

## インストール

### 前提

- **root + LSPosed**（推奨）、または
- **root なし + LSPatch**（Spotify へのパッチ適用はご自身で）

> 未パッチの Spotify では動作しません。Xposed フレームワークの注入に依存しています。

### 手順

1. [Releases](https://github.com/junxi8686/SpotifyPlusPlus/releases) から最新 APK をダウンロードしてインストール
2. **LSPosed** → **モジュール** → **Spotify++** を有効化
3. **スコープ**で `Spotify` にチェック
   - Android Auto の歌詞も使うなら `Android Auto` も
4. **Spotify を強制停止**（設定 → アプリ → Spotify → 強制停止）
5. Spotify を開き直す

> ⚠️ **手順 4 は省略できません。** APK のインストールでは Spotify のプロセスは再起動されず、LSPosed はプロセス起動時にのみモジュールを読み込みます。省略すると古いコードをテストすることになります —— トラブルシューティングで最も混乱しやすい点です。

## 最初の設定

インストール後、曲を再生するだけで歌詞が表示されます。

調整したい場合：

- **歌詞ソース一覧** —— 歌詞画面のソースボタンから、各ソースの一致状況の確認、個別の再チェック、手動指定ができます
- **設定** —— Spotify の設定内にある **Spotify++** セクション

### 調整の例

| 目的 | 方法 |
|---|---|
| 逐字歌詞を優先 | 既定で有効、設定不要 |
| 特定ソースを優先 | 設定 → ソース順序で先頭へ移動 |
| 中国語曲を簡体字で | 既定で有効（同順位で簡体字優先） |
| 自動追従を止めて手動スクロール | 「再生に追従」をオフ |
| 歌詞がずれる | 設定 → 歌詞同期をリセット |

## バックアップと移行

**設定 → バックアップを書き出す** で `Downloads/Spicy EX/SpicyEX-backup.json` に JSON を出力します。

含まれる内容：

| 内容 | 備考 |
|---|---|
| すべての設定 | 外観・描画・動作オプション |
| **AI API キー** | 暗号化して保存 |
| **SpicyLyrics.org クライアントキー** | 暗号化して保存 |
| **ソース順序と曲ごとの選択** | 調整した優先順位 |
| **カタログ全体** | 各曲がどのソースに候補を持つか、一致方法、チェック済みか |
| SpicyLyrics.org のキー改訂とアクセス状態 | 復元後に古い結果が混ざらないように |

復元は **設定 → バックアップを読み込む** でその JSON を選択します。

> **読み込みは上書きです。** 先に一度書き出しておくと安全です。
> 診断ドラフトとキャプチャバッファは**含まれません** —— 進行中のレポートの一時状態だからです。
> **形式は後方互換**：古いバックアップも読み込めます。ファイルにない項目は変更されず、消去もされません。

## ソースからビルド

### ツールチェーン

| 項目 | バージョン |
|---|---|
| JDK | 17 |
| Android SDK | Platform 35（compileSdk 35 / minSdk 27） |
| Gradle | 8.14.2（wrapper 同梱） |
| Android Gradle Plugin | 8.8.2 |

### コマンド

```bash
git clone https://github.com/junxi8686/SpotifyPlusPlus.git
cd SpotifyPlusPlus
./gradlew :app:assembleDebug          # 出力: app/build/outputs/apk/debug/
./gradlew :app:testDebugUnitTest      # 単体テスト
```

Windows では `gradlew.bat` を使用してください。

## トラブルシューティング

<details>
<summary><b>インストールしたが何も起きない</b></summary>

1. LSPosed でモジュールが有効かつ**スコープで Spotify にチェック**が入っているか確認
2. **Spotify を強制停止して開き直す** —— 必須です
3. Spotify のバージョンが対応範囲か確認（本ビルドは 9.1.88 に対応）

</details>

<details>
<summary><b>繁体字で表示されるが簡体字が欲しい</b></summary>

同順位なら簡体字が自動で優先されます。それでも繁体字なら：

1. **歌詞ソース一覧**を開き、簡体字の逐字を出すソースがあるか確認
2. あれば手動で先頭に固定
3. なければ、その曲にはまだ簡体字の歌詞が存在しません

</details>

<details>
<summary><b>特定のソースが何も見つけない</b></summary>

**歌詞ソース一覧**でその行をタップして個別にチェックしてください：

- **チェックマーク** → そのソースにこの曲の歌詞がある
- **×** → 本当に無い、または通信に失敗

カタログの収録状況は**変動します** —— 今日無くても明日あるかもしれません。

</details>

<details>
<summary><b>SpicyLyrics.org が何も返さない</b></summary>

1. キーが `sl_pk_` で始まり、保存に成功したか確認（結果は必ず表示されます）
2. ソース一覧で**一度手動でタップ** —— 手動チェックは「明示的な復帰」経路を通り、以前のアクセス遮断を解除できます
3. サーバーに拒否されたキーはそのソースを一時停止させます

</details>

<details>
<summary><b>機種変更後の復元</b></summary>

**バックアップの書き出し／読み込み**を使います。注意点：

- キーはファイル内で**暗号化**されていますが、暗号鍵は端末に紐づきます —— 機種変更後は**キーの再入力**が必要です
- それ以外（設定・ソース順序・カタログ）は通常どおり復元されます

</details>

<details>
<summary><b>歌詞がずれる</b></summary>

設定 → **歌詞同期をリセット**。保存されたオフセットを消し、再生クロックに再アンカーします。

</details>

## 既知の問題

- 一部の曲はマイナーなソースで一致が遅い（ネットワーク要因であり、モジュールの問題ではありません）
- Android Auto の歌詞は車載ヘッドユニットでの検証が十分ではありません
- ごく一部の曲で歌詞の長さが楽曲と一致しないことがあります（長さ超過チェックで大半は除外）

問題は [Issues](https://github.com/junxi8686/SpotifyPlusPlus/issues) へ、以下を添えて報告してください：

- Spotify のバージョン
- モジュールのバージョン
- 再現手順
- 関連するスクリーンショット

## このフォークの変更点

本リポジトリは [Spicy EX](https://github.com/amarinne/spicy-ex) **v2.0.0** を本プロジェクトの **v1.1** にマージし、以下を調整しています：

### 簡体字中国語

- `values-zh-rCN` を追加し、全文字列リソースを網羅
- 上流で「Java が参照しているがリソースに存在しない」ため中国語 UI が英語に戻る問題を修正
- 歌詞クレジットやエラーメッセージなど動的な文言をローカライズ
- 一部端末で言語一覧が現在の言語しか出ず、切り替えて戻れない問題を修正

### 歌詞マッチング

- **品質優先のランキング** —— 上流 v2.0.0 は「ソース優先」（主ソースを決め、その中でのみ時間軸を比較）に変更したため、より良い代替ソースが主ソースを置き換えられなくなりました。本フォークは「時間軸 > 完全性 > 一致の確実さ > プロバイダ」に戻し、簡体字優先を維持
- **複数ソースの同時取得** —— 上流は 1 つずつ順に問い合わせるため待ち時間が全ソースの合計でした。現在は同時に問い合わせ、最初に使えるものを表示し、厳密に高評価のときだけ置き換えます
- **曲名で検索** —— 自動一致に失敗したら自分で検索して選択
- 簡体字↔繁体字の相互検索と別名・表記ゆれ（「1 文字違いを別の曲として扱う」問題を修正）
- **ソース一覧は曲ごとに 1 回だけチェック**し、成功のたびに通知しなくなりました

### その他

- **Apple Music をソースから削除**
- **バックアップを 2 ストアから 6 ストアに拡張** —— 上流は設定とキーのみで、復元するとカタログが空・ソース未選択でした
- リポジトリ名を含まない誤った GitHub リンクを 3 か所修正
- 設定の「問題を報告」を削除（ドラフトは上流のトラッカー宛で、このフォークには届きません）
- Spotify 9.1.88 の曲取得に対応（上流の書き方では `NoSuchMethodException` を投げ、自動検索が完全に停止します）

詳細は [MODIFICATIONS.md](MODIFICATIONS.md) と [FEATURES_USER.md](FEATURES_USER.md) を参照してください。
