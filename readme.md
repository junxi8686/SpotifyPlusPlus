非官方项目，与 Spotify、Spicy Lyrics 均无关联。

## 这是什么

一个运行在 Spotify 进程内的歌词模块，**基于 [Spicy EX](https://github.com/amarinne/spicy-ex)**（作者 [amarinne](https://github.com/amarinne)）修改而来，主要面向中文用户。

**本仓库是修改版，不是原项目。** 上游的版权归原作者所有，本仓库的修改部分同样以 **AGPL-3.0** 发布 —— 详见 [LICENSE](LICENSE) 与 [NOTICE](NOTICE)。

它做的事很简单：**让你看到的歌词是对的那一份**。

Spotify 自带的歌词只来自它自己的供应商（中文常常是繁体、逐行），而中文歌最好的歌词往往在 QQ 音乐或网易云上（简体、逐字、带翻译）。本模块会同时向多个歌词来源发起查询，取回全部候选后按**质量**排名 —— 时间轴精度优先，其次完整性，再次匹配身份，同级别时简体优先 —— 然后把最好的那份渲染到 Spotify 的歌词界面上。

## 功能

### 歌词获取

- **6 个歌词来源并发搜索** —— 所有已启用的来源同时发起请求，最快的先显示，评分严格更高时才替换
- **逐字歌词**（卡拉 OK 效果），支持逐行、逐词、逐字四档时间轴
- **智能匹配** —— 支持精确 Spotify ID、歌名搜索、繁简互搜、别名与拼写变体（例如「反乌托邦 - 拼接版」与「拼接乌托邦」）
- **按名称手动搜索** —— 自动匹配失败时可以自己搜歌名，从返回结果里挑，按 ID 直接取词
- **歌词来源列表** —— 每个来源单独检查，显示匹配状态、时间轴级别、翻译与能力，可手动置顶
- **本地缓存** —— 取回过的歌词会存下来，再听同一首歌无需重新请求

### 歌词显示

- **翻译**与**罗马音 / 注音**
- **全屏歌词界面**（接管 Spotify 原生歌词页）
- **桌面歌词**与 **PiP（画中画）**歌词
- **Android Auto 歌词** —— 全屏播放器与卡片
- **HyperGlow** 歌词投送
- 对唱视图、背景人声标记、分享卡片

### 匹配质量

- **简体优先** —— 同等级别下优先简体文本，避免「明明有简体却显示繁体」
- 时间轴健康度检查 —— 拒绝时间轴错乱、越界或与录音长度不符的文档
- 毒化文档过滤 —— 拒绝内容可疑的响应

### 其他

- **完整简体中文界面**，另含 English / 日本語 / 한국어 / Русский
- **备份与恢复** —— 设置、密钥、来源顺序、每首歌的选择、整个曲库一次带走

## 歌词来源

| 来源 | 说明 | 需要密钥 |
|---|---|---|
| **SpicyLyrics.org** | 社区歌词库，质量高、常有逐字 | ✅ 需 `sl_pk_` 客户端密钥 |
| **Spotify** | Spotify 自带（常为逐行，中文可能为繁体） | ❌ |
| **AMLL** | Apple Music 风格逐字歌词库 | ❌ |
| **LRCLIB** | 开放歌词库 | ❌ |
| **QQ 音乐** | 中文歌逐字最全，常有翻译 | ❌ |
| **网易云音乐** | 中文歌覆盖广，常有翻译 | ❌ |

> **Apple Music 已移除**，不再作为歌词来源。

### 默认优先级

```
逐字 (Syllable)  >  逐词 (Word)  >  逐行 (Line)  >  无时间轴 (Static)
```

**时间轴级别优先于来源身份** —— QQ 音乐的逐字歌词会胜过 Spotify 的逐行歌词，即使 Spotify 是「原生」来源。同级别时才会比较来源能力与简繁。

### SpicyLyrics.org 密钥

该来源需要你自己的客户端密钥：

1. 打开 **https://developers.spicylyrics.org/catalog/spicy-ex** 申请
2. 密钥格式必须以 **`sl_pk_`** 开头
3. 填入：**设置 → SpicyLyrics.org 客户端密钥**

格式不符会拒绝保存并提示。没有密钥时该来源自动跳过，其余 5 个来源照常工作。

## 安装

### 前置条件

- **已 root + LSPosed**（推荐），或
- **无 root + LSPatch**（需自行给 Spotify 打补丁）

> 本模块无法在未打补丁的 Spotify 上工作，它依赖 Xposed 框架注入。

### 步骤

1. 从 [Releases](https://github.com/junxi8686/SpotifyPlusPlus/releases) 下载最新 APK 并安装
2. 打开 **LSPosed** → **模块** → 启用 **Spotify++**
3. **作用域**勾选 `Spotify`
   - 需要 Android Auto 歌词时再勾 `Android Auto`
4. **强制停止 Spotify**（设置 → 应用 → Spotify → 强制停止）
5. 重新打开 Spotify

> ⚠️ **第 4 步不能跳过。** 安装 APK **不会**重启 Spotify 进程，而 LSPosed 只在进程启动时加载模块。跳过这步你会测试到旧代码 —— 这是排查问题时最常见的困惑来源。

## 首次使用

装好后直接播放一首歌，歌词会自动出现。

需要调整时：

- **歌词来源列表** —— 点歌词界面右下角的来源按钮，可以看每个来源的匹配情况、单独重新检查、或手动指定
- **设置** —— 在 Spotify 设置里找到 **Spotify++** 分区

### 调优建议

| 想要的效果 | 怎么做 |
|---|---|
| 优先逐字歌词 | 默认已开启，无需设置 |
| 优先某个来源 | 设置 → 来源顺序，把它拖到前面 |
| 中文歌显示简体 | 默认已开启（同级别简体优先） |
| 歌词不跟随 / 手动滚 | 关闭「跟随播放」 |
| 歌词不同步 | 设置 → 重置歌词同步 |

## 备份与迁移

**设置 → 导出备份** 会写出一份 JSON 到 `下载/Spicy EX/SpicyEX-backup.json`。

包含：

| 内容 | 说明 |
|---|---|
| 全部设置 | 界面、渲染、行为选项 |
| **AI API 密钥** | 加密存储 |
| **SpicyLyrics.org 客户端密钥** | 加密存储 |
| **来源顺序与每首歌的选择** | 你调好的优先级 |
| **整个曲库** | 每首歌有哪些来源候选、匹配方式、是否检查过 |
| SpicyLyrics.org 密钥版本与访问状态 | 避免恢复后旧结果污染 |

导入用 **设置 → 导入备份**，选那个 JSON 即可。

> **导入是覆盖写入。** 建议先导出一次留底。
> 诊断草稿与抓取缓冲**不在备份内** —— 那是进行中报告的临时状态。
> **格式向后兼容**：旧备份仍可导入，文件中没有的项保持不动、不会被清空。

## 常见问题

<details>
<summary><b>装了没反应 / 功能没生效</b></summary>

1. 确认 LSPosed 里模块已启用，**作用域勾选了 Spotify**
2. **强制停止 Spotify 再打开** —— 必须
3. 确认 Spotify 版本受支持（本版针对 9.1.88 适配）

</details>

<details>
<summary><b>歌词是繁体，但我想要简体</b></summary>

正常情况下同级别会自动优先简体。如果仍显示繁体：

1. 打开**歌词来源列表**，看是否有来源提供简体逐字
2. 若有，手动把它置顶
3. 若没有，说明该曲目暂无简体歌词可用

</details>

<details>
<summary><b>某个来源一直查不到</b></summary>

在**歌词来源列表**里点那一行单独检查：

- **打勾** → 该来源有这首歌的歌词
- **红叉** → 该来源确实没有，或网络不通

注意**上架下架是动态的** —— 今天没有不代表以后没有。

</details>

<details>
<summary><b>SpicyLyrics.org 没有输出</b></summary>

1. 确认密钥以 `sl_pk_` 开头并已保存成功（保存时会有提示）
2. 在来源列表里**手动点它**一次 —— 手动检查会走「显式恢复」路径，可解除之前的访问限制
3. 密钥被服务端拒绝过会导致该来源暂停

</details>

<details>
<summary><b>换手机 / 刷机后怎么恢复</b></summary>

用**备份导出/导入**。注意：

- 密钥在备份文件里是**加密**的，但加密用的密钥绑定设备 —— 换设备后需要**重新输入密钥**
- 其余设置、来源顺序、曲库都可以正常恢复

</details>

<details>
<summary><b>歌词不同步 / 越拖越偏</b></summary>

设置 → **重置歌词同步**。它会清掉偏移量并让模块重新对齐播放时钟。

</details>

## 相对上游做了什么

本仓库把 [Spicy EX](https://github.com/amarinne/spicy-ex) **v2.0.0** 合并到本项目的 **v1.1** 之上，并做了以下调整：

### 简体中文

- 新增 `values-zh-rCN`，覆盖全部字符串资源
- 修复上游「Java 引用了但资源里不存在」导致中文界面回退英文的问题
- 歌词署名、错误提示等动态文案的汉化
- 修复某些设备上语言列表只剩当前语言、切过去切不回来的问题

### 歌词匹配

- **质量优先的选优算法** —— 上游 v2.0.0 改为「来源优先」（先定主来源，只在来源内部比时间轴），导致更好的备用来源永远无法替换主来源。本仓库恢复为「时间轴 > 完整性 > 匹配身份 > 提供者」，并保留简体优先
- **多来源并发请求** —— 上游逐个来源顺序请求，等待时间等于所有来源之和；现在同时发起，最快先显示、更优才替换
- **按名称搜索歌词** —— 自动匹配失败时可手动搜索、自行挑选
- 繁简互搜与别名变体（修复「一个字之差就当成两首歌」）
- **来源列表每个曲目只自动检查一次**，且成功时不再刷屏提示

### 其他

- **Apple Music 来源移除**
- **备份扩展到 6 个存储** —— 上游只备份设置和密钥，导入后曲库为空、来源未选
- 修复三处指向错误地址的 GitHub 链接
- 移除设置里的「报告问题」入口（草稿发往上游，本仓库收不到）
- 适配 Spotify 9.1.88 的曲目获取（上游写法在新版会抛 `NoSuchMethodException`，导致自动搜索整体失效）

详见 [MODIFICATIONS.md](MODIFICATIONS.md) 与 [FEATURES_USER.md](FEATURES_USER.md)。
